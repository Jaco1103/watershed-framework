# Watershed

### A cognitive operating system for AI-assisted projects.

**▶ [See the live demo →](https://jaco1103.github.io/watershed-framework)** — a 90-second walkthrough of what it is and how it works.

Watershed is one file you drop into your project and tell your AI to read. It gives the AI a structured way of thinking *before* it builds anything — a shared map that keeps the whole project visible at once and makes sure the right questions get asked in the right order. Not rules, not a rigid workflow. One file.

---

## The 30-second pitch

Most AI-assisted projects fail the same way: the AI agrees with everything, generates impressive-sounding solutions immediately, context fragments across sessions, and the work collapses into a pile of disconnected ideas that never ship.

Watershed fixes this by turning the AI into a sparring partner instead of a yes-man. It walks you through a sequence of operators — strategy, then architecture, then constraints, and so on — each one a real conversation that writes its conclusions to a single living project document. Every step reads what came before and sets up what comes next. The river deepens as it flows.

No setup. No plugins. No configuration. Drop in one file, answer the first question, keep going.

---

## How it works

Watershed guides you and your AI through seven operators — each one a conversation that builds on the last:

| Operator | Purpose |
|---|---|
| `/strategy` | Understand the vision. Who it's for, what it does, where it's going. |
| `/archetype` | Define the system. Structure, tools, stack, and how it fits together. |
| `/constraints` | Map the fragility. What breaks, scales poorly, or costs too much. |
| `/evaluation` | Define success. What does good actually look like? |
| `/prototype` | Reality arrives. The smallest useful version, built and tested. |
| `/observability` | Make it visible. How do we know what the system is actually doing? |
| `/orchestration` | Strengthen the flow. Reduce fragmentation. The current holds. |

An eighth operator, `/reflect`, sits outside the chain and is available from day one. Bring it any new idea, feature, or pivot at any point and it measures that idea against everything the project already knows about itself — then routes it back to the right step or parks it for later.

Each operator writes its conclusions to a living project document, and each one generates the next command — so finishing `/strategy` makes `/archetype` appear in the picker.

## How you use it

1. Drop the Watershed core file into your project folder
2. Tell your AI: **"Read it."**
3. Answer its first question: *"What are you working on?"*

From there it runs the operators with you and keeps the project's memory current. For a full walkthrough of every operator and what gets built, see [docs/overview.md](docs/overview.md).
